The ShooterCore plugin is Lyra's primary gameplay content plugin. It contains the assets for Lyra's core gameplay features, including the ShooterHero and its ability sets, the Elimination and Control Point game modes, the Blueprint classes for all player weapons, and the assets for bot behavior/construction.

This folder is very dense and its contents are spread out across 18 subfolders. Therefore, this breakdown will cover an overview of each of these subfolders and go more in-depth on important files and folders.

Accolades

The Accolades folder contains seven assets used for award messaging. AccoladeDataRegistry is a Data Registry asset that manages metadata for elimination streaks and multi-eliminations. This registry sources its information from DT_BasicShooterAccolades, a Data Table that defines individual achievements and associates them to with Gameplay Tags and MetaSound assets.

EAS_BasicShooterAccolades is a Lyra Experience Action Set that applies several Gameplay Message Processors to the client. These processors listen for Gameplay Tags and send Gameplay Messages which the UI picks up to display achievements. They include B_AccoladeRelay, which is a generic handler that ensures messages are broadcast to the UI; B_ElimChainProcessor, which tracks "Chains" (multiple consecutive eliminations); B_EliminationFeedRelay, which processes eliminations into "Elimination Feed", the kill messages seen on the left of the UI; and B_ElimStreakProcessor, which tracks "Streaks" (multiple eliminations within the same life).

Blueprint

The Blueprint folder holds Blueprint Actors for Lyra's weapon spawners and launchpads, as well as a few others.

B_WeaponSpawner and B_AbilitySpawner are both subclasses of ALyraWeaponSpawner. B_WeaponSpawner spawns a specific weapon and delivers it to a player, unless they already have the weapon, in which case it refills the player's ammo reserves. B_AbilitySpawner is an effect pad, which can be used to give the player Gameplay Effects. It is configured by default to grant GE_InstantHeal_Part, which heals 25% of the player's health, and is used in L_Expanse for both small and large (50%) health drops.
Both of these spawners can be configured in the details panel; you can adjust the light and item spawn position, and input a LyraWeaponPickupData asset which tracks default spawn cooldown, pickup sound, and pickup mesh. In addition to this, B_WeaponSpawner allows you to specify whether the pickup provides extra ammo, and B_AbilitySpawner allows you to input a Gameplay Effect to apply to the player.

B_GrantAbilityPad_ApplyGE, B_GrantInventory_Pad, and B_GrantInventoryPad_WithMesh are primitive versions of the weapon and ability spawners, which contain all of the information needed instead of referencing other assets to obtain that information. B_GrantAbilityPad_ApplyGE grants GE_InstantHeal_Big, which restores 50% of the player's health. B_GrantInventoryPad_WithMesh is a fully set-up asset inheriting from B_GrantInventory_Pad which gives the player a rifle.

The launcher assets B_Launcher_Push and B_Launcher_Up both inherit from B_Launcher, which is a base launcher class that handles material setup, player VFX, and overlap events. The code for the Overlap function is blank in the main Blueprint, and is overridden in the child actors _UP and _Push. This code is used for the launch physics.

B_PerTestSpawner and B_PerfTestActor are used in L_ShooterPerf as a performance test. B_PerfTestSpawner spawns a stack of B_PerfTestActors, which each have a simple Blueprint script to imitate the performance cost of having a lot of actors in the scene.

Bot

The Bot folder holds the Blueprint Classes, Behavior Trees, and Environment Queries that make up Lyra's robotic combatants. The folder contains five assets and three subfolders in its root.
B_AI_Controller_LyraShooter manages the high-level state and decision-making logic for the bots, while B_AI_Controller_LyraShooter_Passive is an empty graph version for non-reactive AI.
B_ShooterBotSpawner is a data-only Blueprint which specifies bot counts and name pools. The variant B_ShooterBotSpawner_Perf is used in the L_ShooterPerf map and defines spawn conditions for 20 bots.
EQS_Tester is a pawn class for testing the Environmental Query System.

The BT (Behavior Tree) folder houses BT_Lyra_Shooter_Bot. The tree defines two main branches, which filter logic based on whether the bot has ammo. If it does not, it will clear its focus and find a weapon. If the bot does have ammo, it will look for an active enemy. If it does not find one, it will reload and search for either a weapon or an enemy and move towards it.
This folder also contains the BT's Blackboard (BB_Lyra_Shooter_Bot) used for storing info on ammo reserves and enemy position, and a Behavior Tree Decorator that determines if a cheat is disabling the bot's ability to fire.
Rather than handling low-level logic directly, the tree, delegates events to the Gameplay Ability System (GAS), Services, and Decorators.

The EQS folder contains Environmental Query assets. These queries help the bots find enemies, control points, and weapon pickups. The folder also holds EnvQueryContext files, which define reference points for certain actors, and a Generator that creates grid points for evaluation by the Behavior Tree.

The Services folder holds Behavior Tree Services, which run code at a defined tick interval. These assets help perform tasks such as checking ammo levels, setting focus, and shooting. Unlike Decorators, which act as conditional gates in a Behavior Tree, Services perform continuous background updates as long as their branch of the tree is active.

Camera

The Camera folder houses the ThirdPersonADS Camera Mode. In Lyra, Camera Modes consist of two parts: LyraCameraMode and an associated Vector Curve. The LyraCameraMode defines properties such as Field of View (FoV), camera collision, and offset blending.

Vector Curve is used to precisely control the camera's offset from the player. It provides curve data for the X, Y, and Z axes, and is referenced by the LyraCameraMode. This maintains modularity and allows a dedicated graph to edit camera curves.

Effects

The Effects folder is divided into three primary subfolders: Environmental, Material, and Mesh.

The Environmental folder contains two Niagara Systems. NS_CapturePoint is an effect used above capture points, providing a visual outline. NS_CapturePointCounter functions as the progress wheel for capture points.

The Material folder holds Materials and Material Instances for various effects, including those for jump pads/launchers. The Mesh folder contains the Static Mesh used by NS_CapturePoint as the control point's corner boundary.

GameplayCues

The GameplayCues folder contains Gameplay Cue Notifies, which listen for Gameplay Tags and activate audio or effects at a specific location. This folder uses three class types to manage the lifecycle of Gameplay Cues:

  • GameplayCueNotify_Burst: Executes immediately upon activation. Optimized for instantaneous, one-shot events that do not require ongoing logic.
  • GameplayCueNotify_BurstLatent: Begins execution on activation and supports async scripts and latent actions. It persists until the logic has finished, making it ideal for effects requiring a fixed duration.
  • GameplayCueNotify_Looping: Allows persistent effects through four lifecycle events: On Application, On Looping Start, On Recurring, and On Removal. These effects will remain active until the triggering Gameplay Tag is removed or the player is eliminated.

Also in this folder are two Blueprint Widgets: W_MatchDecided_Message for post-match results, and W_WaitingForPlayers_Message which shows team selection and a "WAITING FOR ADDITIONAL PLAYERS" message.

System

The System folder contains two subfolders: Audio and Playlists.
The Audio folder houses WeaponAudioFunctions, a Blueprint Function Library containing various functions for weapon sound logic. This library contains many functions for Spatial audio such as "whiz-bys" for projectiles passing in close proximity to the player.
The Playlists folder contains two LyraUserFacingExperienceDefinition used for map and Game Mode discovery in L_DefaultEditorOverview. They define UI metadata and loading params for L_ShooterGym and L_ShooterPerf.

Weapon

The Weapon folder holds B_Grenade, an Actor Blueprint that defines the projectile's runtime behavior. It handles player collision and explosion timers, as well as physical velocity and rotation.

In addition, the Blueprint has a teleportation script; before going through a portal, the script conserves the grenade's velocity and temporarily deactivates its Projectile Movement Component. Upon exiting the destination portal, it calculates a new directional velocity by multiplying the exit portal's Forward Vector by the conserved velocity (with a dampening multiplier). This ensures a seamless teleportation.
