The Content folder is houses Lyra's core content, including the main lobby, shared UI, and the basic pawn classes. It has 17 subfolders and four files in its root. Of those, only twelve folders are used for gameplay content; the remaining folders are Editor tools, localization files, or legal files. The folder's files and subfolders are categorized and outlined below:

Gameplay Content

Files

B_LyraGameInstance

B_LyraGameInstance is a Blueprint subclass of ULyraGameInstance. It exposes the UObject to the Editor and adds two variables called MusicSystem and Audio_LobbySelect, which are both Audio components.

B_LyraGameMode

B_LyraGameMode is a data-only Blueprint subclass of ALyraGameMode, a subclass of AModularGameMode, which is in turn a subclass of AGameMode. This Blueprint is not actually used in Lyra; all of the settings are the defaults from the C++ classes. The Blueprint is used as an in-editor interface for developers to quickly change settings without having to modify and recompile C++.

DefaultGame_Label

DefaultGame_Label is a Data Asset derived from UPrimaryAssetLabel. This Data Asset is used for labeling assets for the cooker to bundle. Any assets that are listed in the Data Asset will get the label "DefaultGame_Label" and will be bundled together in a package under that name. This asset can be reused to manage bundles when cooking your project.

DefaultGameData

DefaultGameData is a Data Asset derived from ULyraGameData. This asset sets Gameplay Effects that deal with damage, healing and dynamic tags.

Folders

Audio

The Audio folder houses all of Lyra's sound assets, including sound effects, lobby music, mixes, etc. It has 11 subfolders and one file in its root. Rather than spread the audio files throughout Lyra's various plugins, Epic put all of them in the Content folder.

The contents of this folder are outlined below:

  • Attenuation Presets - Sound Attenuation files that handle falloff and occlusion
  • Blueprints - music components, a wind system, weapon audio macros and a general audio helper function
  • Classes - Sound Classes which group sounds and allows control over the group's volume, pitch, and modulation at runtime before routing into a submix; Lyra exposes them in the user Audio settings
  • Concurrency - Sound Concurrency files that limit the number of instances a sound can have and determines how to get rid of overflow
  • Effects - Submix Effects that modify groups of sounds (submixes); presets include:
    • SubmixEffectConvolutionReverbPreset - convolution reverb using an impulse response
    • SubmixEffectDynamicsProcessorPreset - dynamics control
    • SubmixEffectFilterPreset - high pass/low pass filters
    • SubmixEffectTapDelayPreset - multi-tap delay/echo per tap
  • Impulses - Impulse Response (IR) files and their associated audio files, used to create realistic reverb in audio. In Lyra these were combined with the SubmixEffectConvolutionReverbPreset Submix Effect preset to generate reverb by convolving the IR with game audio
  • MetaSounds - MetaSound Source and Patch files, which procedurally generate sound effects or music at runtime. This does come with an overhead CPU cost, but it can also reduce memory usage since it is procedural (smaller footprint, and one file can create a lot of variations). This folder notably holds the main lobby music as well as the sounds for many interactable objects such as jump pads, weapon pads, and portals
  • Modulation - Control Buses, Control Bus Mixes, and Parameter Patches, which work together to control sound modulation based on a float channel at runtime
  • Sounds - Sound files for a large portion of Lyra's gameplay; this folder has both regular sound files (Sound Waves) and MetaSounds
  • SoundWaves - This folder only houses Sound Wave files; it has three folders called Foley (footstep assets), SFX, and Weapons
  • Submixes - Sound Submixes that apply the final effects to each Sound Class (via Submix Effects) before routing the sounds into a master submix for output
  • DYN_LowMultibandDynamics - A Submix Effect handling multiband compression; it uses the preset SubmixEffectMultibandCompressorPreset
Characters

The Characters folder holds the base pawn classes for Lyra, as well as the SimpleHeroPawn used in the L_DefaultEditorOverview map and the UE4/UE5 Mannequin meshes. It has three subfolders and one file in its root.

The contents of this folder are outlined below:

  • Cameras

    The Cameras folder holds the assets for two camera types: ThirdPerson and ThirdPersonDeath. Each type of camera has two assets, a Camera Mode and an Offset Curve. Both camera types are very similar.

    Both Camera Modes are data-only Blueprint subclasses of ULyraCameraMode_ThirdPerson. These assets are the base of a camera mode and determine both how the camera should act and where it should be positioned relative to the player pawn. The Blueprints have settings for camera collision, transition blending, field of view, and offset curves, which are determined by the Offset Curve assets.

    The Offset Curves are Vector Curve assets which are used to offset the camera from the player.

  • Cosmetics

    The Cosmetics folder has six Blueprints and one material. Four of the Blueprints are used to link the meshes and tags together. B_CharacterSelection and B_PickRandomCharacter have logic to choose whether the player gets the Manny or Quinn mesh; B_PickRandomCharacter chooses based on a random seed whereas B_CharacterSelection gets the number of active players and returns a value to determine the mesh.

    M_TeamColorBasic is a material that assigns a base color called TeamColor (defaults to a bright yellow) and creates a glow around the player that matches launch pad colors. It uses Material Functions to create the launch edge glow as well as to determine the effect's kill edge (cutoff), masked opacity, and custom UV data, which is unused.

  • Heroes

    The Heroes folder holds the majority of the assets for Lyra's base hero pawn class. It also contains the UE4/UE5 mannequin meshes and animation sets, the base ability set for Lyra's default pawn, pawn data assets, and the assets that make up the SimpleHeroPawn, which is used in L_DefaultEditorOverview.

    B_Hero_Default

    B_Hero_Default is Lyra's basic hero class. It inherits from the Character_Default Blueprint. This Blueprint has functions for death handling, including a ragdoll animation sequence and the destruction of related actors (like the nameplate).

    SimpleHeroPawn

    B_SimpleHeroPawn is a pawn Blueprint inheriting from B_Hero_Default. It holds no extra functions and is simply a construction script. M_SimpleHeroPawn is the material used for the simple pawn character, and it has an interesting material graph which generates a solid chromium texture. B_SimpleHeroPawn is attached to the SimplePawnData Data Asset, which gives it the third person camera class as well as a basic movement set (walk/jump/crouch).

  • Character_Default

    Character_Default is a Blueprint subclass of ALyraCharacter. It is responsible for sending events to pawn components. All of the logic resides in the parent class. This is the base class that pawn components should be built off of.

ContextEffects

TThe ContextEffects folder contains three assets that use gameplay tags to determine the sounds produced when a player walks or lands on a particular surface. This system could also be used for other things such as Niagara effects (e.g. trailing particles on a specific surface). The surface types defined in the Data Tables are Default, Player, Concrete, and Glass.

Effects

The Effects folder contains Lyra's visual effects systems; particles, UI cards, and all of the supporting textures and materials. It has 13 subfolders.

The contents of this folder are outlined below:

  • AnimationNotifies - Two Anim Notify assets, AN_FootPlant_Left and Anim_FootPlant_Right. The left foot asset is marked for deprecation within the Blueprint graph while its right foot counterpart is data-only, suggesting it may already be deprecated; these notifies were used to signal a system (likely ContextEffects) when a character's foot hit the ground
  • Blueprints - Blueprints for footstep particles, weapon impact decals, muzzle flash, and damage number particles
  • Camera - Player damage screen particle systems and textures
  • Curves - Color Curves and a curve atlas for pyro effects
  • DataChannels - A Niagara Data Channel for weapon impact decals; this asset tracks the position of projectiles and what surface they hit
  • EffectTypes - Niagara Effect Types used for effect spawning rules and scalability per effect type; can prevent certain effects from spawning on low-end hardware or limit the number of instances an effect can have
  • MaterialFunctions - Assorted Material Functions used throughout Lyra
  • Materials - Materials, flipbooks, and meshes used for various effects in Lyra including damage numbers, grenade explosions, launchpad effects, and portals
  • Meshes - Random Static Meshes used in Niagara particle effects including the bullet shells for the weapons and some rubble
  • NiagaraModules - Niagara Module Scripts that cover a variety of effects; these scripts largely handle particle and decal spawn logic
  • Particles - Niagara Particle Systems and Emitters; folders include Environmental, Explosion, Footsteps, Impacts, Item, Lighting, and Weapons
  • Physics - A few assets that make up B_ShatterSphere, which is supposed to break apart using Chaos Physics, but appears unfinished, and an example physics field asset
  • Textures - Image Texture assets used in many of the materials in the Materials folder; this folder only houses independent textures, as asset-specific textures are housed with the asset
Environments

The Environments folder has very little gameplay content. It has one file and two subfolders in its root. B_LoadRandomLobbyBackground is used in L_LyraFrontEnd to create a loading screen while initializing the main lobby. The Materials folder holds a couple of grid textures used in level prototyping. The Gameplay folder holds Blueprints for gameplay effect pads, which are used in test levels for healing and damage testing, and an InstantHeal ability set.

Feedback

The Feedback folder has two subfolders: CameraShakes and Haptics.

  • CameraShakes contains Legacy Camera Shake Blueprints that define the movement of the camera when the player takes damage, is healed, or fires a weapon
  • Haptics contains Force Feedback Effects which control gamepad vibration; there are haptics for when the player takes damage, is healed, or their weapon fires, and a Weapon_Fire_Auto folder that has Float curves along with the Force Feedback Effect
GameplayCueNotifies

The GameplayCueNotifies folder contains Gameplay Cue Notifies, which run a Blueprint script (or, if no script is created, it activates whatever is set in the Blueprint settings such as sounds and Niagara effects) when a specific Gameplay Tag is active. Lyra uses three kinds: GameplayCueNotify_Burst, GameplayCueNotify_BurstLatent, and GameplayCueNotify_Looping.

  • GameplayCueNotify_Burst runs immediately after activation
  • GameplayCueNotify_BurstLatent begins running on activation and can run async scripts before terminating
  • GameplayCueNotify_Looping exposes four events: On Application, On Looping Start, On Recurring, and On Removal; this allows for processes that run constantly or in a loop until the Gameplay Tag is removed
GameplayEffects

The GameplayEffects folder contains Gameplay Effect Blueprints which are data-only assets that grant Gameplay Tags to players. They can be assigned through Ability Sets or granted dynamically at runtime.

Input

The Input folder houses the input data for both B_Hero_Default and SimpleHeroPawn. It contains Input Actions (IAs) that determine how an ability is activated (i.e. via button pressed or held down), an Input Mapping Context which collects all of the IAs into one place and allows you to assign which button or input each is tied to, and Input Data assets that collect IAs and determine which tags are activated by each.

There is also a Lyra Aim Sensitivity Data Asset called GamepadAimSensitivity_Normal, which creates a sensitivity preset for a range of values. These presets can be found in the controller sensitivity settings inside the game UI.

System

The System folder holds much of Lyra's default and frontend data. It has one file and five subfolders in its root.

  • TransitionMap is the map used to transition between different levels during loading
  • DefaultEditorMap holds L_DefaultEditorOverview, which is set as the default startup map in a fresh Lyra project, as well as the Blueprints that assemble the level teleporters in this map; B_ExperienceList3d gets a list of LyraUserFacingExperienceDefinition assets and creates an array of B_TeleportToUserFacingExperience for the user to interact with
  • Experiences holds B_LyraDefaultExperience, which is a Lyra Experience Definition used in L_DefaultEditorOverview to spawn SimpleHeroPawn as the default pawn and create the UI widgets used in that level
  • FrontEnd contains the L_LyraFrontEnd map, as well as its associated experience and a material used in the level
  • Playlists has two LyraUserFacingExperienceDefinition assets for L_DefaultEditorOverview and L_LyraFrontEnd
  • Teams holds four Lyra Team Display Assets, which provide the colorations for Blue, Green, Red, and Yellow teams
UI

The UI folder holds all of Lyra's UI. Everything from the frontend to loading screens to the settings menu, as well as the gameplay UI for both remote and touchscreen devices, is stored here. Most of the files are Widget Blueprints; however, a few other assets are used for storing data and fonts.

Weapons

The Weapons folder contains the static meshes, textures, and materials for items such as the Grenade, Healthpack, and all three ranged weapons, as well as some other miscellaneous assets. This folder is more of an "items" folder than a "weapons" folder.

A key asset in this folder is B_Weapon, which has logic for dynamic team color switching, weapon firing, fake projectiles, weapon impact, weapon switching, and weapon decals/effects. This Blueprint covers all of the gun types in Lyra, and acts as a base for any ranged weapon.

Editor Tools/Content

Editor

This folder holds a single image under Editor/Slate/Icons called CheckContent.svg. It is used for the content validation button at the top of the main Editor window.

Legal

Lyra's Legal folder contains an OFL (Open Font License) .txt file.

Localization

The Localization folder holds localization files for changing Editor and game localizations.

PhysicsMaterials

The PhysicsMaterials folder holds three Physics Materials for Character, Concrete, and Glass, which correspond to the Lyra Context Effects.

Tools

The Tools folder contains Editor tools for level design. Lyra uses Dynamic Mesh Actors, which are Blueprints that can be shaped in-editor using labeled handles on the mesh. Dragging these handles around will change certain aspects of the mesh. These Dynamic Meshes are ideal for level blockouts and greyboxing.

Dynamic Meshes can be baked into Static Meshes for playtesting and final builds. Baking converts the mesh into an optimized, non-editable asset, which increases runtime performance. If a designer needs to further edit the mesh, the asset can be converted back into a Dynamic Mesh.
